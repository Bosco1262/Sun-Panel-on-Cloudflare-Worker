# Sun-Panel-on-Cloudflare-Worker vs 上游部署站样式对比报告

- 上游部署：https://navi.boscopersonal-hk.top/ → **Sun-Panel v1.8.1**（versionCode 26，来自 `/api/about`）
- 本仓库：基于 **Sun-Panel v1.3.0** 前端的 Cloudflare Worker 移植（frontend `package.json` version 1.3.0，naive-ui **2.45.3**）
- 上游打包产物中的类名为 `n-color-picker-trigger / n-color-picker-trigger__fill`（naive-ui < 2.37 才有的旧类名），说明上游部署用的是**旧版 naive-ui**，颜色面板内部结构差异掺杂了组件库版本因素
- 采集条件：两边同视口 1280×720、亮色主题，取自真实渲染的 computed style

## 一、新增项目弹窗：颜色选择器里的"竖条"是什么？

**是 naive-ui 颜色选择器自带的"透明度棋盘格"，不是 bug。**

补充暗色模式下的精确机制（后续实测确认）：

- 触发器内部两层：棋盘格层 `border-radius: 10px`（跟随圆角），颜色覆盖层 `border-radius: 0px`（直角）。
- 默认值 `#2a2a2a6b` 含 42% 透明度 → 直角覆盖层是半透明的，透出**圆角的棋盘格** → 视觉上是一个"胶囊/椭圆形"，且棋盘格的纵向交替条纹明显。
- 选择实色后 → 覆盖层变成不透明直角矩形，完全盖住棋盘格 → 变成"长方形"。
- "右侧的小竖条" = 右端棋盘格圆角收尾与直角覆盖层/深色背景之间错位形成的暗色竖向区域（圆角收尾在上下角留下的暗色缺口 + 直角覆盖层边缘）。实色状态下颜色直角矩形填满同一区域，竖条随之消失。
- 暗色模式下棋盘格与深色背景对比强烈，所以这个现象在暗色模式特别明显（亮色模式下几乎看不出来）。上游部署站采用同样的触发器结构（旧版 naive-ui 的 `n-color-picker-trigger__fill` 同样是"棋盘格 + 覆盖层"两层），行为一致。

### 上游 v1.8.1 的处理方式（暗色模式实测）

上游**没有做任何特殊处理**，触发器内部是完全相同的两层结构、同样的圆角不一致：

| 层 | 上游 v1.8.1 | 本仓库 |
|---|---|---|
| 棋盘格层圆角 | 3px | 10px |
| 颜色覆盖层圆角 | 0px（直角） | 0px（直角） |
| 填充区高度 | 18px | 18px |

- 上游选默认色 `#2a2a2a6b`（暗色模式）：棋盘格同样透出，但 3px 圆角在 18px 高的填充区上只是轻微收角 → 看起来接近长方形，角部暗色缺口仅 ~3px → **没有明显的"椭圆"感和"右侧竖条"**。
- 上游选实色（`#18A058`）：不透明覆盖层盖住棋盘格 → 长方形、无竖条，与仓库一致。
- 结论：上游只是因为全局圆角是 naive-ui 默认的 3px，把这个瑕疵压缩到肉眼几乎不可见；仓库全局圆角 10px（为对齐上游 v1.8.1 RoundCardModal 内部的 10px）放大了同一个瑕疵。且上游自身也不统一——上游新增弹窗内是 3px、RoundCardModal 内是 10px，仓库是统一 10px。

**已实施方案 B**（2026-09-24）：在 `frontend/src/styles/global.less` 末尾新增全局规则：

```less
.n-color-picker .n-color-picker__fill,
.n-color-picker .n-color-picker-checkboard {
	overflow: hidden;
	border-radius: 3px !important;
}
```

要点：
- 需同时覆盖填充区**和棋盘格层**——棋盘格层自身带 10px 圆角，只裁剪填充区时两层圆角取交集仍呈胶囊形。
- 圆角需 `!important`：naive-ui 的 cssr 样式在运行时追加到 `<head>`，比打包的全局样式更晚注入，同特异性下会覆盖。
- 暗色模式实测：默认半透明值 `#2a2a2a6b` 与实色 `#F0A020` 两种状态均渲染为一致的 3px 圆角近似长方形，"椭圆 + 右侧竖条"消失（像素级采样确认：填充区顶部行与中部行的起止位置一致）。

- 卡片背景色的默认值是 `#2a2a2a6b`（8 位 HEX），后两位 `6b` ≈ **42% 不透明度**。
- naive-ui 的触发器（`n-color-picker__fill`）内部渲染顺序：灰白棋盘格 → 半透明颜色覆盖层（`rgba(41,41,41,0.42)`）→ 色值文本。默认值带 alpha，棋盘格就透出来。
- 触发器宽 ~274px、高仅 18px，棋盘格一格 6.7px，只有 2~3 行、几十列——视觉上主导的是**纵向交替的灰白条纹**，看起来就像"颜色右边/上面有一条竖着的条"。
- 上游 v1.8.1 的同位置**同样显示棋盘格**（默认值同为 `#2a2a2a6b`），两边行为一致。
- 验证：一旦选中实色（如色板里的 `#F0A020`），值变成 6 位 HEX，覆盖层变为不透明 `rgb(239,159,31)`，棋盘格立即消失。
- 另外：弹窗内容区 `.h-[500px].overflow-auto` 在展开"更多选项"后内容 636px > 500px，右侧会出现一根 **5px 宽的圆角灰条（滚动条）**，全局样式见 `frontend/src/plugins/scrollbarStyle.ts`；Windows Chrome 下不悬停/不滚动会自动隐藏。若你指的是紧贴弹窗右缘的那根，就是它。

可选处理（如想去掉棋盘格观感）：
1. 维持现状（与上游一致，且能直观表达"半透明背景"）；
2. 默认值改用纯色 `#2a2a2a`（会偏离上游观感）；
3. 显示时剥离 alpha、保存时保留（改动最大，不推荐）。

## 二、新增里的背景色选择 vs 设置里的颜色选择器

**同一个 `NColorPicker`、同样的 props（`show-alpha=false`、`size=small`、`modes=['hex']`），组件层面无差别。** 观感差异来自数据：

| 位置 | 当前值 | 触发器观感 | 色板 (swatches) |
|---|---|---|---|
| 新增-卡片背景色 | `#2a2a2a6b`（带 alpha） | 透出棋盘格（显条纹） | 6 个，首个 `#2a2a2a6b` 也是半透明 |
| 设置-搜索栏边框颜色 | `#cccccc`（实色） | 均匀色条 | 4 个 |
| 设置-搜索栏占位文字颜色 | `#cccccc`（实色） | 均匀色条 | 4 个 |
| 设置-文字颜色 | `#ffffff`（实色） | 均匀色条 | 5 个 |

与上游 v1.8.1 相比，这个选择器面板还有一处行为差异（见下表第 3 条）：上游是 HEXA 模式 + 透明度滑条（alpha 可编辑），本仓库锁成了 HEX-only。

## 三、两边都存在、但 CSS 不一样的地方（实测）

> **2026-09-24 更新：以下第 1、3、4、5 项已按上游对齐实施并验证，见文末「已实施的对齐」。**
> 另有一处勘误：早前报告中"上游分组编辑弹窗内部为 10px 圆角"是采集时浏览器标签页切换失误所致（误测了本仓库）；上游干净复测为 **3px**，即上游全部控件统一 3px。

### 1. 全局控件圆角：仓库 10px vs 上游 3px（最系统性的一处）——✅ 已对齐

- 根源：仓库 `frontend/src/hooks/useTheme.ts` 曾设置 `common.borderRadius: '10px'`；上游全部控件走 naive-ui 默认 `3px`。
- 登录页：输入框 / 登录按钮同为 350×34，圆角 10px vs 3px。
- 新增项目弹窗内（尺寸完全相同，仅圆角不同）：`NInput` 165.7×29.4、`NSelect`、各按钮、保存按钮 56×34、颜色选择器触发器。

### 2. 新增弹窗"更多选项"区布局不同（未对齐，属功能性差异）

- 仓库 2 列：卡片背景色（触发器宽 **274px**）+ 分组；代码注释注明有意省略"卡片类型"。
- 上游 3 列：卡片背景色（**175.3px**）+ 分组 + 卡片类型下拉。

### 3. 颜色选择器面板（点开后）内容不同——✅ 已对齐（卡片背景色）

- 仓库（改前）：HEX 模式、无透明度滑条、色板 6 个。
- 上游 v1.8.1：默认模式（rgb/hex/hsl）+ **透明度可编辑**（HEXA 显示 + 2 根滑条），色板 8 个：`#2a2a2a6b, #000000, #ffffff, #18A058, #2080F0, #F0A020, #D03050, #C418D1`。
- 上游分组管理的文字颜色选择器为 HEX + 无 alpha + 5 色板，与本仓库 `ItemGroupManage` 的选择器**本来就一致**，无需改动。
- 上游 v1.8.1 的"个性化设置"是重新设计的页面（LOGO/时钟/搜索栏等组件开关），与仓库"风格设置"无 1:1 对应，故仓库风格设置页的 3 个选择器保持原样。

### 4. "系统应用"设置弹窗尺寸不同——✅ 已对齐

- 仓库：900×566（内容区高 500px）→ 上游：**1000×666**（内容区高 600px），圆角均为 1rem。

### 5. 设置页下拉框尺寸不同——✅ 已对齐

- 我的信息页语言/主题下拉：上游 **200×28**（宽 200 + small 尺寸）；仓库宽度本就是 `max-w-[200px]`，高度由 34px（medium）改为 28px（small）。
